## Hypothesis and acceptance

Hypothesis: ordinary App display-link creation/FPS-setting currently performs unused target-class/association bookkeeping. Narrowing that bookkeeping to its non-SpringBoard Float host removes the unnecessary work without changing 120Hz requests or Float-host behavior.

Success in host integration fixtures: ordinary-App association operations are zero; Float-host metadata still works; SpringBoard remains excluded; original factory return value and 120/120/120 range/FPS sinks are unchanged. The constant-time visible-cache semantics are not changed by this implementation.

Independent failure signals: any metadata/prearm newly enabled in SpringBoard; loss of Float-host source activation; any ordinary-App request no longer reaches the 120Hz sink; changed ownership/retry/cadence; changes to files outside the narrow runtime scope.

No magnitude of CPU, FPS, thermal or battery improvement is claimed. If A/B/A on-device does not show repeatable improvement without regressions, do not publish this as a smoothness fix.
